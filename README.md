# 极简记账

> 版本 2.2.0 · 包名 `com.lele.ledger` · Android 应用

只做一件事：**读取微信、支付宝、银行的付款通知，自动记一笔账。**  
没有登录、没有云同步、没有家庭账本、没有 AI、没有 VIP。所有数据只存在手机本地。

---

## 项目解决什么问题

手动记账坚持不了三天。不是意志力问题，是每次付完钱还要打开 App 输入金额、选分类太麻烦。

所以不如让 App 在后台等着——你正常付款，App 监听到通知后自动提取金额和渠道，写入本地账本。

自动记账兜不住的情况（现金、线下、别人的手机付的、通知没来的），首页右下角「＋」可以手动补一笔。

---

## 主要功能

### ⚡ 自动记账
监听系统通知，解析微信/支付宝/各银行 App 的付款文案，自动提取金额、判断收支方向、识别渠道，写入本地账本。精确去重，不会产生重复账单。

### ➕ 手动记一笔
首页右下角悬浮按钮，填金额、选收支方向、选用途，一步存进同一个账本。

- 方向必须显式选：自动记账的方向由通知文案决定，手动记账没人替你判断
- 用途随方向切换词表（支出 12 类 / 收入 8 类）；换方向会清掉已选用途，避免留下选不中的幽灵值
- 手动记录渠道标为「手动」，在列表和饼图里与自动记录并列统计
- 不做去重：连点两次保存就是真想记两笔，拦下来反而更坏

### 📊 月度看板
首页顶部英雄卡显示**本月收入 / 本月支出 / 净结余**，支持左右翻看上/下月。

### 🏷️ 用途分类（钱迹风格）
记完账后弹出横幅通知，让用户选择这笔钱用在了什么地方。支出 12 类（餐饮、交通、购物、服饰、日用、居住、通讯、娱乐、医疗、学习、人情、其他），收入 8 类（工资、奖金、兼职、退款、红包、理财、报销、其他）。固定词表，不允许自建——保证饼图统计有意义。

### 🥧 收支占比饼图
按月查看支出花在哪、收入从哪里来。未分类的单独一档，提醒用户去补。

### 🔔 转账确认
微信转账「已被接收」的通知里**没有金额**，方向也有歧义。App 绝不猜——先存为待确认提案，用户手动填金额、选方向后再写入账本。记错账比多问一步坏得多。

### 💰 月度预算
- 设置月度总预算，进度条实时显示已用百分比
- 可对单个分类（如「餐饮」「购物」）设独立预算
- 花到 80% 自动弹预警通知，超支也提醒
- 进度条颜色：绿（安全）→ 黄（预警）→ 红（超支）
- 首页显示本月剩余日均可用额度

### 📥 微信账单导入
支持导入微信 CSV 和 xlsx 格式账单，自动编码检测（GBK/UTF-8），只导入已到账记录，按交易单号去重。支持文件选择器或直接打开文件。

### ✏️ 记录编辑与删除
- 点击任意记录修改金额、选用途
- 右划单条删除（二次确认）
- 长按进入多选模式，支持全选、批量删除

### 🔍 原始通知排查
每条通知原文都在 App 里可查，排查故障不用连电脑。有心跳标记（★）用来判断服务是否活着。

### 🌙 深色模式
支持浅色/深色切换，自动记住用户选择。

### 🚀 开机自启
手机重启后自动拉起常驻服务（需在系统自启动管理中允许）。

## 安装方法

### 方式一：直接安装 APK

将 `app-release.apk` 传到手机上直接安装即可。

### 方式二：自行编译

需要安装（合计约 8–12 GB）：

1. **JDK 17**（推荐 Eclipse Temurin 或 Microsoft OpenJDK）
2. **Android SDK 命令行工具** + `platforms;android-34` + `build-tools;34.0.0`（Android Studio 会自动带）
3. 设置环境变量 `ANDROID_HOME` 指向 SDK 目录

```bash
cd jizhang-app
.\gradlew.bat assembleRelease
```

产物：`app/build/outputs/apk/release/app-release.apk`

> 首次运行 `gradlew` 会自动下载 Gradle 发行包（约 130 MB），需要联网。

### 方式三：解析规则回归测试

```bash
node rule-test.mjs
```

34 条真实文案用例全部通过，覆盖微信/支付宝/银行、付款/收款/退款/千分位、转账待确认、以及必须忽略的假通知。

## 使用方法

### 装到手机后必做的六步

**第 6 步不做等于白装：**

1. **授予通知使用权**  
   设置 → 通知与状态栏 → 通知使用权 → 打开「极简记账」（App 首页按钮可直达）

2. **关闭电池优化**  
   设置 → 电池 → 电池优化 → 找到它 → 不优化（App 首页有按钮）

3. **允许自启动**  
   设置 → 应用 → 自启动管理 → 打开

4. **锁定后台**  
   多任务界面下拉卡片加锁 🔒

5. **微信/支付宝的通知必须开着**  
   微信 → 我 → 设置 → 新消息通知，确认「微信支付」通知没被静音

6. **去付一笔款，验证自动记账**  
   没有这一步，上述所有设置都可能是白做的。

### 日常使用

- **记账**：正常付款即可，自动记入，列表实时刷新
- **补记**：右下角「＋」手动填一笔（现金、线下、通知没来的）
- **选用途**：弹出横幅时点击，或从首页顶部横幅进入，也可点列表中任意记录补选
- **看饼图**：首页底部「用途占比」按钮
- **设预算**：首页预算行或抽屉菜单
- **删错账**：右划删除，或长按进入多选模式批量删除
- **导入账单**：首页底部「导入微信账单」
- **查故障**：抽屉菜单 →「原始通知」

### ColorOS / 一加特别说明

国产系统后台管控是本 App 头号杀手。第 2–4 步缺一不可。系统更新后可能重置，需要重新检查。

## 输入输出示例

### 自动记账

**输入**（微信支付通知）：
```
Weixin Pay
支出 ¥18.50
商户信息：7-Eleven 便利店
```

**输出**（写入数据库后首页显示）：
```
本月支出        ¥18.50
7-Eleven 便利店  微信   -¥18.50
```

### 微信账单 CSV 导入

**输入**（微信导出的 `微信账单.csv`）：
```csv
交易时间,交易类型,交易对方,商品,收/支,金额(元),支付方式,当前状态,交易单号
2026-09-15 12:30:00,商户消费,7-Eleven,便当,支出,18.50,微信支付,已到帐,202609151230001234
2026-09-15 19:20:00,转账,张三,,收入,200.00,微信支付,已到帐,202609151920004567
```

**输出**（导入结果弹窗 + 首页刷新）：
```
✅ 成功导入: 2 笔
本月收入 ¥200.00  本月支出 ¥18.50
张三 · 微信导入  +¥200.00
7-Eleven · 微信导入  -¥18.50
```

### 转账确认

**输入**（微信转账通知）：
```
张三
转账已被接收
```

**输出**（App 弹出待确认页面）：
```
张三
微信 · 转账已被接收

[我转出的]  [我收到的]  ← 选择方向
[输入金额]              ← 手动填写
[确认]  [忽略]
```

用户确认后记为：
```
张三  微信   -¥200.00
```

### 预算预警

当月餐饮预算 ¥1,000，花到 ¥830（83%）时弹出通知：

```
预算预警
「餐饮」已花 ¥830.00，达预算 83%，剩余 ¥170.00
```

首页进度条变黄。

### 饼图

本月有餐饮 ¥1,200、交通 ¥300、购物 ¥500、其他 ¥200，支出饼图显示：

```
饼图：本月支出  ¥2,200

餐饮   55%   ¥1,200
交通   14%   ¥300
购物   23%   ¥500
其他    9%   ¥200
```

### 原始通知排查

```
原始通知（最近 50 条）：

[09-22 12:30:05] ★ · 心跳 · 监听服务仍在运行
[09-22 12:28:00] com.tencent.mm · Weixin Pay · 支出 ¥18.50
```

有★标记且时间新鲜 → 服务活着，通知也收到了 → 去查解析规则。  
★标记停在某个时刻不更新 → 服务被杀 → 检查保活设置。

## 项目结构

| 文件 | 作用 |
| --- | --- |
| `NotiListener.java` | 通知监听服务（核心入口），接收系统通知 |
| `BillParser.java` | 通知文案 → 金额 + 收支方向 + 渠道 |
| `Db.java` | 本地 SQLite 数据库，账本、原始通知、待确认转账、分类预算共 4 张表 |
| `MainActivity.java` | 主界面：汇总英雄卡 + 月份切换 + 记录列表 + 预算条 + 编辑/删除/多选 + 手动记一笔 |
| `Bill.java` | 记录模型 |
| `BillAdapter.java` | 列表适配器，支持右划删除、长按多选 |
| `BillNotify.java` | 记账后弹横幅通知提醒用户选用途 |
| `Category.java` | 固定用途词表 + 稳定颜色映射 |
| `CategoryChips.java` | 用途选择 Chip 网格组件 |
| `CategorizeActivity.java` | 单条记录快速选用途 |
| `UncategorizedBulkActivity.java` | 未分类记录列表，批量定用途 |
| `PieChartView.java` | 纯自绘饼图控件 |
| `PieActivity.java` | 收支占比饼图页 |
| `Budget.java` | 月度预算 + 分类预算 + 预警通知 |
| `BudgetActivity.java` | 预算设置页 |
| `KeepAliveService.java` | 常驻前台服务（保活核心） |
| `TransferActivity.java` | 转账待确认页 |
| `ImportActivity.java` | 微信账单 CSV/xlsx 导入 |
| `CsvImporter.java` | CSV 解析器 |
| `ExcelImporter.java` | xlsx 文件解析器 |
| `WeChatAccessibilityService.java` | 辅助功能备选方案 |
| `SmsObserver.java` | 短信监听备选方案 |
| `BootReceiver.java` | 开机自启 |

解析规则改编自 [FuShengDuoBuYu/AutoBookKeepingBeta](https://github.com/FuShengDuoBuYu/AutoBookKeepingBeta)（MIT 协议，已保留署名）。相对原版修正了渠道名含「支付」二字导致收款被误判为支出方向的 bug。
